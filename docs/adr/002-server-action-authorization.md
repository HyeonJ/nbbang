# ADR-002: 모든 서버 액션은 검증·인가 미들웨어를 통과한다

2026-09-11 · 상태: 승인

## 결정

모든 쓰기는 next-safe-action으로 정의하고, 공통 미들웨어에서
① zod로 입력을 파싱하고 ② 세션에서 `userId`를 확인하고 ③ 대상 `groupId`의 멤버십·역할을 조회해
`{userId, groupId, role}` 컨텍스트를 만든 뒤에만 도메인 로직을 호출한다.
v1 권한: 쓰기는 `owner`(총무)만, `member`는 열람. 예외를 두지 않는다.

## 이유

- `'use server'` 함수는 **공개 HTTP POST 엔드포인트**다. TypeScript 타입도, 클라이언트 검증도, 컴포넌트 경계도 서버에 도달하는 페이로드를 제한하지 않는다. 돈을 다루는 앱에서 액션 하나의 인가 누락은 곧 장부 조작 경로다.
- 액션마다 손으로 검사하면 "잊은 액션"이 반드시 생긴다. 미들웨어로 강제하면 누락이 구조적으로 불가능해진다.
- 도메인 함수는 인가된 컨텍스트만 받으므로 순수하게 유지되고, 단위 테스트가 쉬워진다.

## 기각한 대안

- **액션별 수동 체크**: 규율 의존 — 확장하면서 반드시 구멍이 생긴다.
- **API Route + 미들웨어**: 같은 효과지만 서버 액션의 폼 통합·타입 전달을 포기하게 됨. v1 구조(단일 앱)에선 safe-action이 더 적은 코드로 같은 보장.
