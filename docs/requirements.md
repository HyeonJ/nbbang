# 엔빵 — 제품 요구사항 (PRD)

2026-09-11 확정 (브레인스토밍 승인분). 변경 시 이 문서를 먼저 고치고 코드가 따라간다.

## 1. 문제

모임(동호회·스터디)의 회비 관리는 총무 한 사람의 수작업이다.
엑셀 + 카톡 스크린샷 + 기억으로 운영되며, 세 가지 스트레스가 반복된다:

1. **누가 냈는지 추적** — 매달 납부자를 손으로 대조
2. **엔빵 계산** — 회식·이벤트 비용을 참여자끼리 나누고 송금 경로를 정리
3. **투명성 질문** — "회비 어디에 썼어요?"에 매번 스크린샷으로 답변

## 2. 페르소나

**"민지"** — 30대 배드민턴 동호회 총무. 멤버 ~20명, 월 회비 2만원.
코트비·셔틀콕을 본인 카드로 결제하고 모임 통장에서 정산한다.
엑셀은 다룰 줄 알지만 매달 반복 작업이 귀찮고, 미납자에게 독촉하는 게 제일 스트레스다.

- 보조 페르소나: 멤버 — 가입시키면 안 쓴다. **로그인 없이** 링크로 장부를 보고 싶어한다.

## 3. 핵심 플로우 (v1)

| # | 플로우 | 설명 | 상태 |
|---|---|---|---|
| F1 | 모임 개설·멤버 관리 | 모임 생성, 초대 링크 합류, 총무(owner)/멤버(member) 역할 | ✅ Plan 01 |
| F2 | 회비 수입 기록 | 월 회차 생성(연월·1인 금액) → 멤버별 납부 체크(일자·메모) | ✅ Plan 02 |
| F3 | 지출 기록 | 금액·항목·일자·메모·카테고리. 정정은 역분개로 | ✅ Plan 02 |
| F4 | 정산 + 열람 | 이벤트 엔빵 계산("누가 누구에게 얼마") + 장부 열람 | ✅ Plan 03 |
| F5 | 공개 장부 링크 | 로그인 없는 읽기 전용 뷰(`/g/[token]`) — 표시 이름만 노출, 토큰 재발급 가능 | ✅ Plan 03 |
| F6 | 미납 복붙 텍스트 | "1월 회비 미납: ○○, ○○ (계좌 …)" 카톡용 텍스트 생성 | ✅ Plan 02·03 |
| F7 | CSV 내보내기 | 장부 전체를 CSV로 | ✅ Plan 03 |

**F4의 v1 범위 정정** — 원안의 "최소 이체"는 다중 채권자 상계(그리디 netting)를 뜻하는 말이었다.
v1은 **선결제자 1명** 모델만 구현한다: 한 사람이 총액을 먼저 내고 나머지가 그에게 보내므로
채권자가 하나뿐이고 상계할 것이 없으며 이체는 최대 n−1건이다. 이것이 요구사항이 예로 든
"회식비 엔빵"을 덮는다. 여러 명이 나눠 낸 정산은 v1 비범위이며, 필요해지는 시점에 도메인
함수 하나(`minimalTransfers`)를 갈아 끼우는 변경이다 ([ADR-003](adr/003-settlement-outside-ledger.md)).

## 4. 비범위 (v1에서 하지 않음)

실결제·PG 연동(개인 프로젝트는 PG 가입에 사업자 필요 — v2에서 샌드박스로 기술 검증),
청구서·알림 발송, 영수증 사진 첨부(v1.5), OCR, 은행 연동, 다중 통화.

## 5. 성공 기준

| 기준 | 상태 | 근거 |
|---|---|---|
| Vercel 프로덕션 배포 + F1~F7 전부 동작 | ✅ | CI `deploy` 잡이 마이그레이션 → 배포를 수행한다. E2E 5본이 매 푸시마다 동선을 확인하고, Plan 03 Task 11에서 **프로덕션 실기기 스모크**(모임→회비→지출→정산→공개 링크→CSV)를 수행한 뒤 데이터를 삭제했다 |
| 실모임 1개 온보딩 | ❌ **미달** | 코드 밖 활동이고 **아직 섭외하지 않았다.** 사람을 받기 전에 있어야 할 것(삭제·탈퇴·처리방침·남용 방지)이 Plan 04에서 채워졌으므로 기술적 선행조건은 더 없다 — 남은 것은 섭외뿐이고, 이 줄이 여전히 유일한 v1 미달 항목이다 |
| 돈 정합성: 잔액 ≠ 원장 합산이 되는 경로가 없음 | ✅ | 잔액 컬럼이 **존재하지 않는다**(ADR-001 — 파생값). 통합 테스트가 DB 왕복으로 `getBalance == balanceOf(entries)`를 고정하고, 복합 FK가 모임 경계를 DB에서 막으며, 정산은 원장을 건드리지 않음이 대시보드·공개 장부·CSV **세 표면**에서 E2E로 고정된다(ADR-003) |

## 6. 제약

- 주 10~15시간 사이드 페이스, v1 목표 7~9주
- 운영비 0원 티어 (Vercel + Neon free)
- 개발자 배경: Java/Spring 7년 — TS 백엔드는 이 프로젝트가 처음 (학습이 목적의 일부)

## 7. 실사용 전 하드닝 (Plan 04) — 닫힌 것

v1 기능 확장이 아니라 **실제 사람을 받기 전의 마감**이다. 넷 다 구현·배포됐다.

| 항목 | 상태 | 근거 |
|---|---|---|
| **공개 링크 레이트 리밋** | ✅ **닫음** | Plan 03이 "v1 미도입으로 결정"하고 *"그 판단이 틀렸다고 판명되면 Plan 04의 첫 항목"* 이라고 적은 항목이다. 실제로 첫 항목이 됐다 — 열거 방어가 아니라 **유출된 링크의 반복 긁기와 함수 호출 비용** 방어가 이유다. `middleware.ts`에서 IP당 분당 60회, 초과 시 429 + `Retry-After`. 서버 컴포넌트는 상태 코드를 낼 수 없어 판정을 미들웨어로 옮겼다. IP는 HMAC 앞 32자만 저장하고 크론이 치운다(상한 최대 48시간) |
| **모임 완전 삭제** | ✅ | 총무가 모임 이름을 타이핑하면 7개 자식 테이블 + `groups`를 한 트랜잭션에서 순서대로 지운다. 대상 목록을 **FK 전이 폐포와 대조**하므로 테이블이 추가되면 테스트가 먼저 빨개진다 |
| **회원 탈퇴** | ✅ | 행 삭제가 아니라 **식별자 파기**다 — `user.id`를 `notNull`로 참조하는 컬럼이 셋이다 ([ADR-004](adr/004-deletion-semantics.md)). 금액·이체 구조는 보존되고 이름만 `탈퇴한 멤버`가 된다 |
| **개인정보처리방침** | ✅ | `/privacy`. 법률 문서가 아니라 코드가 하는 일을 옮긴 **서비스 정책**이다. 무엇이 남는지(내부 UUID·자유 텍스트)까지 적는다 |
| **세션 행의 접속 IP 미보관** | ✅ | Task 4가 발견한 사실(인증 라이브러리가 세션마다 평문 IP·User-Agent를 적는다)을 Task 5에서 닫았다. 공식 스위치는 **같은 플래그로 로그인 레이트 리밋까지 끄므로** 쓰지 않고, `databaseHooks.session.create.before`로 두 값만 비웠다. 통합 테스트가 양쪽(값이 비는 것 · 제한이 여전히 429를 내는 것)을 고정한다 |

## 8. 제품 미결 (Plan 05 이후에서 판단)

기술 부채가 아니라 **아직 만들지 않기로 한 제품 결정**이다. 코드에 TODO로 흩어 두지 않고 여기 모은다.

| # | 미결 | 왜 아직 안 하는가 | 지금 사용자가 마주치는 것 |
|---|---|---|---|
| P1 | **총무 위임** | 소유권 이전은 "누가 지울 수 있는가"를 바꾸는 권한 변경이라 인가 매트릭스 전체에 영향을 준다. 모임이 하나뿐인 지금은 발생 빈도를 알 수 없다 | **총무는 바로 탈퇴할 수 없다.** 소유한 모임을 먼저 삭제해야 한다. 에러 문구가 소유 모임 이름을 나열하고 이 기능이 없다는 사실을 그대로 말한다 |
| P2 | **다중 채권자 정산** (그리디 netting) | **의도적 범위 밖이고, 실사용 한 달 뒤에 판단한다** ([ADR-003](adr/003-settlement-outside-ledger.md)). 필요해지면 도메인 함수 하나(`minimalTransfers`)를 갈아 끼우는 변경이다 | 여러 명이 나눠 낸 정산은 만들 수 없다. v1은 **선결제자 1명** 모델이다 |
| P3 | **이름·표시명 수정 화면** | 계정 이름과 모임 표시 이름을 바꾸는 화면이 없다 | 정정이 필요하면 문의해야 한다. 처리방침의 '이용자의 권리'에 그 사실을 적어 뒀다 |
| P4 | **개인정보 전용 문의 창구** | 실제 이용자가 0명인 상태에서 연락처를 공개하면 관리 대상만 늘어난다 | 문의는 **공개** GitHub 이슈뿐이다. 그래서 처리방침이 "개인정보를 이슈에 적지 마세요"를 경고하고, 열람·삭제는 화면에서 직접 하도록 안내한다 |
| P5 | **자유 텍스트 PII 파기** | 지출 메모·계좌 문구·정산 제목에서 개인정보를 찾아 지우려면 PII 탐지가 필요하고, 남의 이름·모임 이름을 잘못 지우는 문제가 따라온다 | 탈퇴해도 **직접 적은 글자는 남는다.** ADR-004와 처리방침이 그 한계를 명시한다 |
| P6 | **토큰당 레이트 리밋 · 슬라이딩 윈도** | 현재는 IP당 고정 윈도다. 고정 윈도는 경계에서 최대 2배 버스트를 허용하지만 비용 방어에는 충분하다. 토큰당으로 걸면 20명이 링크를 동시에 열 때 정상 사용자가 막힌다 | 윈도 경계에서 순간적으로 한도의 2배가 통과할 수 있다 |
