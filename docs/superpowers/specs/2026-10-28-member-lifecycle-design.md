# 멤버 생명주기 설계 (Plan 05 첫 항목)

> 상태: 설계 승인(2026-10-28) · 요구사항 §8 P0 "멤버 생명주기" · 실모임 온보딩 선행 조건

## 1. 문제

지금 모델에는 "모임을 떠나는 사람"이 없다. 떠나는 방법은 회원 탈퇴뿐이고 그 경우에도 멤버십 행은 남는다(ADR-004).

- `getGroupMembers`가 탈퇴자를 거르지 않는다. 그래서 탈퇴자가 **이후 모든 회차의 미납자**로 잡히고(`미납: 철수, 탈퇴한 멤버`), 기대 총액이 부풀며, 정산 참여자 선택·대시보드·공개 장부 멤버 목록에도 나온다.
- 나가기·내보내기 액션이 없다.
- 회차 명단이 회차의 것이 아니라 **지금** 명단이다. 3월 가입자가 1월 회차의 미납자로 보이고, 회차 화면은 "납부 인원 > 명단" 불일치를 화면에서 따로 처리하고 있다.

## 2. 결정

| # | 결정 | 기각한 대안 |
|---|---|---|
| D1 | 회차 명단은 **회차를 만들 때 고정한다**(스냅샷 테이블). | 기간 계산(joined/left vs 회차 월): 월 중간 가입 규칙을 코드가 정해야 하고 예외를 둘 수 없다. 현재 명단 − 나간 사람: 과거 회차 왜곡이 그대로 남는다. |
| D2 | 멤버 **본인 나가기**와 **총무 내보내기**를 모두 만든다. 총무는 나갈 수 없다(위임은 P1). | 총무만: 멤버가 스스로 정리할 수 없다. 본인만: 연락이 끊긴 사람을 정리할 수 없다. |
| D3 | 나간 사람의 미납은 **그대로 남는다**. 총무는 회차 명단에서 사람을 **빼거나(면제)** 활동 중인 멤버를 **넣을** 수 있다. 납부한 사람은 뺄 수 없다(납부 취소 먼저). | 나가면 자동 제외: 나가기로 빚이 지워진다. 편집 없음: 월 중간 가입자를 넣을 길이 없다. |
| D4 | 스스로 나간 사람이 초대 링크로 돌아오면 **같은 멤버십을 되살린다**(새 이름 입력). **내보내진 사람은 링크로 돌아올 수 없고** 총무가 되살린다. | 구분 없음: 내보내기를 의미 있게 하려면 매번 링크를 재발급해야 한다. 재가입 불가: 실수로 나간 사람도 영영 못 돌아온다. |
| D5 | 저장 모델은 `memberships.left_at` + `left_reason` 컬럼과 `dues_round_members` 테이블이다. | 이벤트 로그(`membership_events`): 지금 이력이 필요한 화면이 없고, 모든 "활동 중" 판정이 집계가 된다. `role`에 상태 값 추가: 권한과 소속이 한 컬럼에 섞이고 시각도 원래 역할도 남지 않는다. |

## 3. 데이터 모델 (마이그레이션 0008)

### 3.1 `memberships`

```
left_at      timestamptz null      -- null = 활동 중
left_reason  text null             -- 'left' | 'removed' | 'withdrawn'
CHECK ((left_at IS NULL) = (left_reason IS NULL))
```

- **"활동 중" = `left_at IS NULL`**, 이 한 가지로만 판정한다.
- `(user_id, group_id)` 유니크는 그대로 둔다. 되살리기는 같은 행의 `left_at`/`left_reason`을 null로 되돌리는 것이므로 행이 둘이 될 일이 없다.
- `joined_at`은 되살릴 때 바꾸지 않는다(정렬 기준이고, 과거 기록과의 연결이 같은 행이기 때문이다).

### 3.2 `dues_round_members` (신규)

```
group_id       text not null
round_id       text not null
membership_id  text not null
PRIMARY KEY (round_id, membership_id)
FK (group_id, round_id)      → dues_rounds (group_id, id)
FK (group_id, membership_id) → memberships (group_id, id)
UNIQUE (group_id, round_id, membership_id)   -- 아래 dues_payments 복합 FK의 참조 대상
```

### 3.3 `dues_payments` — 명단 FK 추가

```
FK (group_id, round_id, membership_id) → dues_round_members (group_id, round_id, membership_id)
```

이 FK 하나가 규칙 두 개를 DB에서 고정한다.
- **명단에 없는 사람은 납부할 수 없다**(insert → 23503).
- **납부한 사람은 명단에서 뺄 수 없다**(delete → 23503, 기본 `NO ACTION`).

그 결과 "납부 인원 > 명단"은 표현 불가능한 상태가 된다. 회차 화면의 `overpaid` 분기와 그 문구는 삭제한다.

### 3.4 백필 (같은 마이그레이션)

1. 탈퇴자: `user.deleted_at IS NOT NULL`인 사용자의 멤버십 → `left_at = user.deleted_at`, `left_reason = 'withdrawn'`.
2. 기존 회차 명단 = **회차 생성 시점에 활동 중이던 멤버**(`joined_at <= created_at` 이고 그때 떠나지 않았음) ∪ **그 회차 납부자**. 합집합의 둘째 항은 3.3 FK가 백필 직후 성립하도록 보장하는 장치다(시계 오차·수동 데이터).
   - 회차 생성 **뒤에** 탈퇴한 사람은 그 회차 명단에 남는다(그 시점의 의무 — D3). 생성 **전에** 떠난 사람은 들어가지 않는다.
3. 순서: 컬럼 추가 → 1 → 테이블 생성 → 2 → `dues_payments` FK 추가. FK를 마지막에 거는 이유는 백필 전에 걸면 기존 납부 행이 위반이기 때문이다.

## 4. "활동 중" 기준이 적용되는 자리

| 자리 | 지금 | 바뀐 뒤 |
|---|---|---|
| `getGroupForMember` (모든 모임 페이지의 접근 판정) | 멤버십 존재 | 활동 중인 멤버십 → 나간 사람은 404 |
| `groupActionClient` (모든 모임 액션의 접근 판정) | 멤버십 존재 | 활동 중 → 아니면 `NOT_MEMBER` |
| `app/groups/page.tsx` 내 모임 목록 | 전부 | 활동 중인 것만 |
| `getGroupMembers` (대시보드·설정·정산 참여자 선택·회비 목록) | 전부 | 활동 중만 |
| `createSettlement` 참여자·선결제자 검증 | 같은 모임 | 같은 모임 + 활동 중 |
| 공개 장부 멤버 목록 (`public-queries.ts`) | 전부 | 활동 중만 |
| `markPaid` | 같은 모임 멤버 | **회차 명단에 있으면 된다**(나간 사람이 빚을 갚는 것은 받는다). 판정은 3.3 FK가 한다. |

과거 정산은 스냅샷(ADR-003)이라 영향이 없다. 원장·CSV에는 멤버 목록이 없다.

## 5. 동작

### 5.1 회차

- **생성(`createRound`)**: 회차 insert와 **같은 트랜잭션**에서 그 순간의 활동 중 멤버 전원을 `dues_round_members`에 넣는다.
- **명단에서 빼기(`removeFromRound`, 총무)**: 해당 행을 지운다. 납부한 사람이면 FK가 막고 → `PAID_MEMBER`로 번역한다.
- **명단에 넣기(`addToRound`, 총무)**: **활동 중인** 멤버만. 이미 있으면 멱등 성공.
- **화면**: 기대 총액·미납자·납부자는 모두 **회차 명단**에서 계산한다. 나간 사람은 이름 뒤에 `(나감)`을 붙인다.
- **미납 안내 문구**(단톡방용)에는 **활동 중인 미납자만** 넣는다. 나간 사람은 단톡방에 없고, 이 문구가 다시 `탈퇴한 멤버`를 부르는 것이 1장의 결함이었다. 나간 미납자는 화면에서만 보이고, 총무가 면제할지 정한다.
- 회비 목록의 `납부 n/m`에서 m은 회차 명단 인원이다.

### 5.2 나가기 · 내보내기 · 되살리기

| 액션 | 누가 | 조건 | 결과 |
|---|---|---|---|
| `leaveGroup` | 멤버 본인 | 총무가 아님 (`OWNER_CANNOT_LEAVE`) | `left_at = now`, `left_reason = 'left'` |
| `removeMember` | 총무 | 대상이 같은 모임의 활동 중 멤버이고 자기 자신이 아님 | `left_reason = 'removed'` |
| `restoreMember` | 총무 | 대상의 `left_reason = 'removed'` | `left_at`, `left_reason` → null |

- 모두 쓰기 트랜잭션 안에서 `assertActiveUser`를 부른다(ADR-004 동시성 규칙).
- 나간 뒤 남는 것: 원장 기록, 납부 기록, 과거 회차 명단, 정산 스냅샷. 바뀌는 것은 소속 상태뿐이다.
- 멤버는 "모임 나가기"를 모임 대시보드에서 본다(설정은 총무 전용이다). 설정 화면에서 총무는 멤버 행마다 "내보내기"를, 그리고 아래에 "나간 멤버" 목록을 본다(사유 표시, `removed`에만 "되살리기").
- 내보내기와 나가기는 확인 단계를 둔다(모임 삭제·탈퇴와 같은 패턴. 다만 되돌릴 수 있으므로 문구 타이핑까지는 요구하지 않는다).

### 5.3 초대 링크로 다시 들어오기 (`joinByInvite`)

| 기존 멤버십 | 결과 |
|---|---|
| 없음 | 지금과 같다(새로 만든다) |
| 활동 중 | `already: true` |
| `left` | 같은 행을 되살리고 새로 입력한 이름으로 바꾼다 |
| `removed` | `REMOVED_FROM_GROUP` |
| `withdrawn` | 도달 불가(세션 단계에서 막힌다). 방어적으로 `REMOVED_FROM_GROUP`과 같게 거절한다 |

- 되살리기는 비교-후-갱신(`WHERE left_reason = 'left'`)으로 한다. 동시에 총무가 상태를 바꾸면 갱신 0행 → 다시 읽어 판정한다.

### 5.4 회원 탈퇴와의 연결

- `anonymizeUserRows`가 그 사용자의 **모든** 멤버십에 `left_reason = 'withdrawn'`, `left_at = coalesce(left_at, now)`를 쓴다. 이미 `removed`였어도 `withdrawn`으로 덮는다. 그래야 `restoreMember`가 이름이 파기된 멤버십을 되살릴 수 없다.
- 이름 파기 범위는 지금과 같다(ADR-004).

### 5.5 이름 입력 검증 (함께 처리)

`createGroup`의 총무 이름과 `joinByInvite`의 이름에 대해:
- 앞뒤 공백은 잘라서 저장하고, 잘라낸 결과가 비면 거절한다.
- 보이지 않는 문자(공백·폭 없는 문자·한글 채움 문자 등 Unicode Default_Ignorable)만으로 된 이름은 빈 이름으로 보고, 앞뒤의 그런 문자는 잘라 저장한다. 이름 안쪽 문자는 그대로 둔다(이름은 유일하지 않아도 된다).
- `탈퇴한 멤버`(`ANONYMOUS_MEMBER_NAME`)는 거절한다. 이 이름은 파기의 표지이고, 살아 있는 사람이 쓰면 공개 장부에서 둘을 구별할 수 없다.

## 6. 동시성

| 경합 | 결과 | 판단 |
|---|---|---|
| `createRound` ↔ `leaveGroup` | 커밋 순서대로 명단에 들어가거나 빠진다 | 허용. 들어갔으면 `(나감)`으로 보이고 총무가 면제할 수 있다 |
| `createRound` ↔ `joinByInvite` | 같은 원리 | 허용. 빠졌으면 총무가 넣는다 |
| `removeFromRound` ↔ `markPaid` | FK가 한쪽을 막는다 | 안전 — 3.3 |
| `restoreMember` ↔ 탈퇴 | 탈퇴가 `withdrawn`으로 덮고, 되살리기는 `WHERE left_reason = 'removed'` 비교-후-갱신이다 | 안전 |

## 7. 범위 밖

- 총무 위임·총무 나가기 (P1)
- 나갈 때 정산 채무 확인: 정산은 원장 밖 스냅샷이고 지급 상태를 추적하지 않는다(ADR-003)
- 멤버십 이력 화면
- 이름 수정 화면 (P3)
- 날짜 유효성(`2026-13-45`) 등 이번 회고의 다른 소소한 항목

## 8. 테스트

**단위**
- 회차 계산(`roundTotals`, `unpaidMembers`)이 명단을 입력으로 받는다. 미납 안내 문구는 활동 중인 미납자만 넣는 순수 함수로 분리해 테스트한다.
- 이름 검증: 공백만, 앞뒤 공백, 예약어.

**통합 (실DB)**
- 마이그레이션 백필: 탈퇴자 표시, 명단 = 생성 시점 활동 멤버 ∪ 납부자, 백필 후 FK가 성립하는지.
- FK: 명단 밖 납부 insert → 23503 / 납부자 명단 삭제 → 23503.
- 회차 생성 스냅샷: 나간 사람은 빠지고, 나중에 들어온 사람은 없다.
- 탈퇴 → 모든 멤버십 `withdrawn`(이미 `removed`인 것 포함), 되살리기 거절.
- 모임 삭제: `dues_round_members`가 삭제 순서에 들어가는지. 기존 FK 전이 폐포 테스트가 새 테이블을 자동으로 요구한다.

**E2E**
- 인가 매트릭스에 **"나간 멤버"** 컨텍스트를 추가한다. 모임 페이지 404, 모든 모임 액션 `NOT_MEMBER`, 공개 장부 열람은 영향 없음.
- 나가기 → 링크로 재가입 → 같은 멤버십(과거 납부가 이어지는지).
- 내보내기 → 링크 재가입 거절 → 총무가 되살림.
- 회차: 나간 미납자는 `(나감)`으로 화면에 보이고 안내 문구에는 없다. 면제하면 기대 총액이 준다.

**변이 확인 (적어도 둘)**
- `getGroupForMember`에서 `left_at` 조건을 빼면 인가 매트릭스가 빨개진다.
- `dues_payments` 명단 FK를 빼면 "납부자 명단 삭제" 테스트가 빨개진다.

## 9. 문서

- ADR-005 "멤버 생명주기": D1~D5, 그리고 "활동 중 = `left_at IS NULL` 하나"라는 규칙.
- 용어집: 나가기 · 내보내기 · 되살리기 · 회차 명단 · 면제.
- 스펙 §2 데이터 모델, requirements §8 P0 → 완료.
